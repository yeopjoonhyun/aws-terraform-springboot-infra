# 02. 네트워크 설계

코드를 쓰기 전에 VPC와 서브넷 구조를 먼저 설계합니다.

## 설계 목표
- 외부에서 접근해야 하는 것(ALB)만 퍼블릭에 둔다.
- 앱(ECS)과 DB(RDS)는 프라이빗에 두어 인터넷에서 직접 접근할 수 없게 한다.
- 가용 영역(AZ) 2개에 분산해 한쪽 AZ가 장애나도 서비스가 유지되게 한다.
- 실습 비용을 고려해, 비싼 리소스(NAT Gateway)는 필요한 시점에만 켠다.

## 구조
```
                      Internet
                         |
                 [Internet Gateway]
                         |
   ┌──────────────── VPC 10.0.0.0/16 ────────────────┐
   │                                                 │
   │  AZ-a (ap-northeast-2a)   AZ-c (ap-northeast-2c)│
   │  ┌────────────────────┐   ┌────────────────────┐│
   │  │ public-a           │   │ public-c           ││
   │  │ 10.0.0.0/24        │   │ 10.0.1.0/24        ││
   │  │ ALB, NAT Gateway   │   │ ALB                ││
   │  └────────────────────┘   └────────────────────┘│
   │  ┌────────────────────┐   ┌────────────────────┐│
   │  │ private-app-a      │   │ private-app-c      ││
   │  │ 10.0.10.0/24       │   │ 10.0.11.0/24       ││
   │  │ ECS(Spring Boot)   │   │ ECS(Spring Boot)   ││
   │  └────────────────────┘   └────────────────────┘│
   │  ┌────────────────────┐   ┌────────────────────┐│
   │  │ private-db-a       │   │ private-db-c       ││
   │  │ 10.0.20.0/24       │   │ 10.0.21.0/24       ││
   │  │ RDS                │   │ RDS(대기)          ││
   │  └────────────────────┘   └────────────────────┘│
   └─────────────────────────────────────────────────┘
```

## IP 대역 계획
| 서브넷 | AZ | CIDR | 용도 |
|---|---|---|---|
| public-a | 2a | 10.0.0.0/24 | ALB, NAT Gateway |
| public-c | 2c | 10.0.1.0/24 | ALB |
| private-app-a | 2a | 10.0.10.0/24 | ECS 태스크 |
| private-app-c | 2c | 10.0.11.0/24 | ECS 태스크 |
| private-db-a | 2a | 10.0.20.0/24 | RDS |
| private-db-c | 2c | 10.0.21.0/24 | RDS 서브넷 그룹용 |

대역을 10단위로 띄운 이유: 용도별로 자리 번호가 구분되어 나중에 서브넷을 추가해도 규칙이 깨지지 않는다.

## 트래픽 흐름
1. 사용자 → Internet Gateway → ALB(퍼블릭)
2. ALB → ECS 태스크(프라이빗 앱 서브넷), 포트 8080
3. ECS → RDS(프라이빗 DB 서브넷), 포트 3306
4. ECS → 인터넷(이미지 pull 등)은 NAT Gateway를 경유

## 보안 그룹 (계획)
| 이름 | 허용 인바운드 | 출처 |
|---|---|---|
| alb-sg | 80, 443 | 0.0.0.0/0 |
| app-sg | 8080 | alb-sg만 |
| db-sg | 3306 | app-sg만 |

보안 그룹의 출처를 IP가 아닌 **다른 보안 그룹**으로 지정해, DB는 앱을 통해서만 접근되도록 한다.

## 비용 고려
- NAT Gateway는 켜 두는 동안 시간당 요금이 발생하므로 실습 후 `terraform destroy`로 삭제한다.
- 비용을 줄이는 대안 후보: VPC 엔드포인트 사용, 학습 중 NAT 대신 퍼블릭 서브넷에 임시 배치.

## 아직 결정하지 못한 것
- NAT Gateway를 AZ마다 둘지(고가용성) 하나만 둘지(비용 절감)
- DB 엔진: MySQL vs PostgreSQL
